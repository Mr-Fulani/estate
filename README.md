# Rahat Home — мультиязычный сайт агентства недвижимости

Полноценное приложение агентства недвижимости: публичный каталог и блог на русском, английском, турецком и арабском, формы обращений и русскоязычная административная панель.

## Возможности

- публичные маршруты `/ru`, `/en`, `/tr`, `/ar` с сохранением раздела при смене языка и полноценным RTL для арабского;
- каталог, фильтры, пагинация, карточка объекта и адаптивная фотогалерея;
- премиальные страницы жилых комплексов с вариантами квартир, интерьерной галереей и планировками; импорт ETRO описан в [docs/residential-developments.md](docs/residential-developments.md);
- переводы названия, описания, адреса и маркетингового статуса объектов с управляемым fallback;
- отдельные SEO title/description RU/EN/TR/AR для каждого объекта, URL по slug, canonical/hreflang, Open Graph/X, `RealEstateListing` JSON-LD и динамический sitemap;
- блог с общим slug, переводами RU/EN/TR/AR и локализованными SEO/Open Graph/JSON-LD данными;
- единый журнал форм, звонков и переходов в мессенджеры с UTM-атрибуцией;
- CRM-воронка от нового обращения до продажи/аренды, история действий, заметки и сумма сделки;
- отзывы с публичной формой, обязательной модерацией, переводами RU/EN/TR/AR и персональными ссылками после сделки;
- дашборд фаундера с новыми обращениями, подтверждёнными сообщениями, активной воронкой, проданными/сданными объектами и суммой сделок;
- админка объектов, новостей, переводов, обращений, категорий и контактов сайта;
- защищённая админка с персональными аккаунтами, ролями, серверными сессиями и журналом действий;
- состояния загрузки, ошибок, 404 и адаптивная навигация.

Архитектурный контракт локализации и блога описан в [docs/architecture-i18n-news.md](docs/architecture-i18n-news.md), SEO и CRM — в [docs/seo-crm.md](docs/seo-crm.md), отзывы — в [docs/reviews.md](docs/reviews.md), Telegram-уведомления — в [docs/telegram-notifications.md](docs/telegram-notifications.md), отложенные задачи — в [docs/technical-debt.md](docs/technical-debt.md).

## Быстрый старт в Docker

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
docker compose up --build
```

Контейнер API автоматически выполняет `alembic upgrade head`. После запуска:

- сайт: [http://localhost:3000/ru](http://localhost:3000/ru);
- админка: [http://localhost:3000/admin](http://localhost:3000/admin);
- Swagger (только development): [http://localhost:8000/docs](http://localhost:8000/docs);
- ReDoc (только development): [http://localhost:8000/redoc](http://localhost:8000/redoc).

Перед первым входом создайте founder-аккаунт. Команда интерактивно запросит пароль и не сохранит его в истории терминала:

```bash
docker compose exec api python -m app.cli create-founder \
  --username founder \
  --email founder@example.com \
  --name "Имя фаундера"
```

После этого откройте `/admin/login` и войдите по логину или email. Самостоятельной публичной регистрации нет: новые аккаунты создаёт founder в разделе «Команда и доступ».

Добавить демонстрационные категории, объекты, переводы и новость в пустую базу:

```bash
docker compose exec api python -m app.seed
```

Seed не удаляет данные и пропускает выполнение, если категории уже существуют.

## Локальная разработка

### Backend

Требуются Python 3.12+ и доступный PostgreSQL.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
cd backend
alembic upgrade head
uvicorn app.main:app --reload
```

### Frontend

Рекомендуется Node.js 20.19+, 22.13+ или 24+.

```bash
cd frontend
cp .env.example .env
npm ci
npm run dev
```

Браузер обращается к API через same-origin прокси `/api/backend`, поэтому защищённые cookie не передаются между разными доменами. `INTERNAL_API_URL` используется серверным рендерингом и прокси внутри Docker. `SITE_URL` задаёт базовый URL canonical и социальных метаданных во время запуска сервера, поэтому один образ можно использовать на разных доменах. В production обязателен реальный HTTPS origin без пути и query; `NEXT_PUBLIC_SITE_URL` больше не используется. Передавайте `SITE_URL` контейнеру web через environment/env_file. `DEPLOYMENT_ENV=test` разрешён только для изолированных тестов.

## Миграции

Новая база поднимается командой:

```bash
cd backend
alembic upgrade head
```

Если база была создана старой версией приложения через `Base.metadata.create_all` и в ней нет таблицы `alembic_version`, сначала сделайте резервную копию и убедитесь, что базовые таблицы соответствуют ревизии `20260822_0001`. Затем выполните:

```bash
cd backend
alembic stamp 20260822_0001
alembic upgrade head
```

Последующие ревизии добавляют новости и переводы, SEO и CRM, отзывы, аккаунты и роли, курсы валют, локализованные адреса, медиагалереи, финансовую целостность сделок, идемпотентность webhook, хеширование приглашений и постоянные лимиты публичных запросов. Проверить состояние схемы можно командой `docker compose exec api alembic check`.

## Авторизация админки

- `founder` — полный доступ, управление командой и безопасностью;
- `admin` — все рабочие разделы и просмотр аудита без управления founder-аккаунтами;
- `manager` — объекты, лиды, сделки, отзывы и категории;
- `editor` — объекты, новости и отзывы.

Сессия хранится на сервере, а браузер получает только `HttpOnly` cookie. Изменяющие запросы дополнительно защищены CSRF-токеном. После пяти неверных паролей аккаунт временно блокируется; общий лимит попыток применяется к IP и email. В журнале фиксируются входы, изменения объектов, статусов лидов и сделок, отзывов, публикаций, категорий, настроек и аккаунтов.

Для production задайте длинный случайный `SECRET_KEY`, включите `AUTH_COOKIE_SECURE=true` и используйте только HTTPS. Для сброса founder-пароля повторно выполните `create-founder` с тем же email.

## SEO объектов

В редакторе объекта для каждого языка доступны собственные SEO title и meta description. При пустых полях сайт безопасно формирует fallback из названия, расположения и описания. Публичный адрес использует slug, например `/ru/properties/kvartira-u-morya`.

- `/sitemap.xml` включает активные объекты только на тех из четырёх языков, для которых заполнен перевод;
- `/robots.txt` закрывает административную часть;
- главное фото объекта используется в Open Graph и X; при отсутствии фото чужое общее изображение не подставляется;
- коммерческий статус отражается в структурированных данных как доступен, ограниченно доступен, продан, сдан или архивирован.

## Обращения и сделки

Форма, телефон и контактные ссылки создают записи в единой CRM. Для перехода сохраняются объект, канал, страница, язык, referrer, UTM и идентификатор сессии. Повторные клики одного посетителя по тому же каналу в течение 30 минут объединяются.

Этапы воронки: `new → contacted → qualified → viewing → negotiation → won/lost`. Для `won` обязательно выбрать результат `sold` или `rented`; связанный объект автоматически получает соответствующий коммерческий статус. В админке сохраняются заметки и история изменений.

Браузер достоверно фиксирует переход в мессенджер, но не может подтвердить отправку сообщения. Для подтверждённых сообщений предусмотрен защищённый webhook:

```text
POST /api/v1/contacts/webhook
X-CRM-Webhook-Secret: значение CRM_WEBHOOK_SECRET
```

Коннектор WhatsApp/Telegram/MAX должен передать `channel`, `external_conversation_id`, `message` и, если известно, `property_id`. Пока внешний коннектор не настроен, дашборд честно показывает такие события как клики, а не как полученные сообщения.

## Отзывы

- Публичная страница: `/ru/reviews`, `/en/reviews`, `/tr/reviews`, `/ar/reviews`.
- Новый отзыв получает статус `pending` и не появляется на сайте автоматически.
- Администратор редактирует автора, оценку, переводы, ответ компании, подтверждение, порядок и признак показа на главной в `/admin/reviews`.
- После успешной сделки в CRM доступна кнопка создания персональной ссылки. Такой отзыв помечается подтверждённым, но всё равно проходит модерацию.
- Контакты автора используются только для проверки и не входят в публичный API.

Публичная форма содержит скрытое honeypot-поле, требует согласие на публикацию и защищена постоянным лимитом запросов в PostgreSQL. На production можно дополнительно включить CAPTCHA на reverse proxy при появлении реального бот-трафика.

## Основные API блога

Публичные:

- `GET /api/v1/news/?locale=ru&page=1&per_page=9`;
- `GET /api/v1/news/{slug}?locale=en`.

Административные:

- `GET /api/v1/news/admin/all`;
- `GET /api/v1/news/admin/{id}`;
- `POST /api/v1/news/`;
- `PUT /api/v1/news/{id}`;
- `DELETE /api/v1/news/{id}`.

### Профиль компании и тексты

После миграции `20260908_0017` откройте **Админка → Настройки сайта**. Заполните название компании, реальные контакты, структурированный адрес, логотип, favicon, изображение социальных превью и фотографии страниц. Затем заполните SEO и тексты для каждого публикуемого языка. Название подставляется в `{brand}`. Юридические тексты и услуги необходимо адаптировать к конкретной компании. Без выбранного изображения общий код не использует фото или OG первого клиента.

Настройки хранятся в `site_settings.profile`, а домен — только в серверном `SITE_URL`. Для новой компании нужны отдельные БД, хранилище медиа и конфигурация развёртывания. Общие исходники менять не требуется. Старые клиентские изображения и демонстрационные seed-данные не становятся настройками нового проекта автоматически.

### Языки и валюты проекта

`SITE_LOCALES`, `SITE_DEFAULT_LOCALE`, `SITE_CURRENCIES`, `SITE_DEFAULT_CURRENCY` и `CATALOG_CURRENCY` задаются одинаково в окружениях API и frontend. Пример проекта без русского: `SITE_LOCALES=en,tr`, `SITE_DEFAULT_LOCALE=en`, `SITE_CURRENCIES=EUR,USD`, `SITE_DEFAULT_CURRENCY=EUR`, `CATALOG_CURRENCY=EUR`. Отключённые языки возвращают 404 и отсутствуют в hreflang/sitemap. Базовые поля объекта имеют собственный `content_locale`; миграция сохраняет язык существующих записей.

Реализованные валюты: RUB, USD, EUR, TRY. Неизвестные коды отклоняются, а при сбое курсов цена остаётся в исходной валюте. Фильтры API принимают суммы в `CATALOG_CURRENCY`. Внутренний формат курсов и существующий CRM-учёт остаются RUB; это явный контракт адаптера CBR XML, а не валюта витрины. `EXCHANGE_RATE_SOURCE_URL` позволяет настроить совместимый источник; для другого формата или новой валюты нужен отдельный адаптер. Быстрые бюджеты главной настраиваются в профиле компании, список категорий берётся из БД.

### SEO-подборки

В **Админка → SEO-страницы** создаются отдельные страницы `/[язык]/collections/[slug]` с собственным текстом и фиксированными условиями каталога: категория, город, продажа/аренда. Публикация требует полного текста на основном языке; неполные переводы не доступны для индексации. Страницы попадают в sitemap и доступны через раздел подборок в подвале. Адрес фиксируется после сохранения; содержание, условия и публикацию можно менять. Генерация страниц из произвольных комбинаций фильтров не выполняется. Для нового агентства нужно написать собственные тексты на основе его фактических услуг и территории работы.

### Sitemap

`/sitemap.xml` формируется из компактного API `/api/v1/seo/sitemap`, который читает опубликованные данные в одной транзакции REPEATABLE READ. Полные описания и фотографии не передаются frontend для построения карты. Последний успешный снимок хранится в памяти процесса 5 минут, при сбое используется до 24 часов; после перезапуска без снимка возвращается 503 с Retry-After. Снимки разделены по origin/API/языкам. При росте создаётся sitemap index с частями `/sitemaps/N.xml`, каждая меньше 45 000 URL и 45 МиБ. Это не долговременный архив; для нескольких экземпляров каждый имеет собственный кеш.

### Индексация production и preview

По умолчанию индексирование выключено. Для публичного проекта задайте `DEPLOYMENT_ENV=production`, `INDEXING_ENABLED=true` и корректный HTTPS `SITE_URL`. В админке должны быть заполнены бренд, хотя бы один контакт, SEO главной на основном языке и отмечена проверка данных/текстов. До этого метаданные содержат noindex, а sitemap пуст. При выключенном окружении дополнительно выставляется X-Robots-Tag.

Для закрытого стенда задайте `DEPLOYMENT_ENV=preview`, `PREVIEW_USERNAME` и уникальный `PREVIEW_PASSWORD` вне Git. В preview индексация выключена независимо от флага; без настроенного доступа стенд отвечает 503, без авторизации — 401. Используйте HTTPS на reverse proxy. Служебные token/preview URL всегда noindex и private/no-store. robots оставляет публичные страницы доступными для чтения noindex.

После выбора сервера настройте на ingress: HTTP → HTTPS и все разрешённые алиасы → origin из SITE_URL постоянным 301/308 с сохранением path/query. Сертификат должен покрывать фактические hostnames; HTTPS, DNS и редиректы проверяются уже на опубликованном домене. Значения домена не должны подставляться из входящего Host. Никакой сервер или DNS этой задачей не публиковался и не изменялся.
