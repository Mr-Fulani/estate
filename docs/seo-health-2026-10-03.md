У всех изображений в проверенном HTML есть атрибут alt; качество формулировок требует отдельной редакционной оценки.

## Найденные улучшения

### 1. Одинаковые description у вариантов жилья — P2

48 страниц вариантов жилья образуют 11 групп одинаковых описаний внутри одного языка. Страницы наследуют начало общего описания ЖК вместо описания конкретной планировки. Это встречается у ETRO, Vadi и Kılıç Life. Часть текста обрезана на середине фразы.

Например, варианты 1+1, 2+1 и 3+1 Kılıç Life получают одинаковое описание проекта. Рекомендация: формировать description из названия проекта, конкретного типа жилья, подтверждённой площади и существенных особенностей варианта. Не подставлять неподтверждённые сроки или цены.

Это не запрет индексации, но страницы хуже различаются в поисковых сниппетах. У Google нет жёсткого лимита description в 160 символов; важнее уникальность и полезность текста. Сам факт длинного описания не считается технической ошибкой. [Рекомендации Google по сниппетам](https://developers.google.com/search/docs/appearance/snippet).

### 2. На основных страницах ЖК отсутствует BreadcrumbList — P2

На 12 страницах трёх ЖК, с учётом четырёх языков, нет BreadcrumbList. У обычных объявлений, вариантов жилья и подборок эта разметка присутствует.

Причина в `frontend/src/components/pages/PropertyDetailContent.tsx`: компонент скрытых хлебных крошек создаётся, но ранний возврат страницы ЖК его не включает.

Рекомендация: добавить существующий компонент с `visible={false}` в ветку ЖК. Визуальное меню хлебных крошек останется скрытым, а структурированная цепочка появится. Отсутствие этой разметки не блокирует обычную индексацию. [Документация Google по BreadcrumbList](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb).

### 3. Видео: превью в исходном HTML и структурированная разметка — P2/P3

В исходном серверном HTML видео получают общую брендовую картинку `/og.png`. Настоящий кадр `.poster.webp` подставляется после выполнения JavaScript. Проверенные реальные превью доступны, поэтому проблема относится к первоначальной разметке, а не к отсутствию файлов.

Причина в `frontend/src/components/properties/PropertyVideo.tsx`: подходящий poster выбирается после загрузки изображения в браузере. Рекомендация: отдавать реальное локальное превью сразу в серверном HTML и использовать брендовую заглушку при ошибке загрузки.

VideoObject в проверенной разметке отсутствует. Для важных видео можно добавить название, описание, thumbnailUrl, contentUrl и достоверную дату публикации; длительность брать из файла. Не придумывать отсутствующие даты.

Это улучшает описание видео для поисковика, но не гарантирует попадание в видеовыдачу: для такого результата Google учитывает, является ли видео главным содержимым страницы. Страница продажи недвижимости не обязательно соответствует этому условию. [VideoObject](https://developers.google.com/search/docs/appearance/structured-data/video), [рекомендации по видео](https://developers.google.com/search/docs/appearance/video).

### 4. Противоречивые метаданные 404 — P3

У проверенной отсутствующей страницы одновременно присутствуют `noindex` и унаследованное `index, follow`, а canonical указывает на `/ru`.

HTTP 404 уже защищает от индексации такой страницы; более ограничивающий noindex также имеет приоритет. Рекомендация: оставить однозначный noindex и убрать canonical на главную для страниц ошибок. Это исправление согласованности разметки, не критическая поломка. [Правила robots meta](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).
