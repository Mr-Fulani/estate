# Общий шаблон жилых комплексов

Один комплекс — одна карточка каталога и отдельная редакционная страница. Типы квартир хранятся в `property_unit_types`, не выдаются за конкретные доступные лоты. Обычные объекты сохраняют прежний интерфейс.

## Локальный запуск и импорт

```bash
docker compose up -d
docker compose exec -T api alembic upgrade head
docker compose exec -T api python -m app.seed_etro
```

Страница: `/ru/properties/etro-residences-istanbul` (также `en`, `tr`, `ar`). Seed идемпотентен: если slug уже существует, данные не меняются. Не запускается автоматически при старте API.

Готовые WebP и PDF находятся в `frontend/public/residences/etro`. `scripts/import_etro_media.py` при необходимости импортирует отсутствующие изображения из предоставленного пользователем Google Drive; нужен Python с Pillow. Существующие файлы не заменяются. Скрипт не импортирует PDF, уже включённый в проект.

Для уже импортированного ETRO: `docker compose exec -T api python -m app.seed_etro --complete-layouts`. Дополняет только отсутствующие параметры планов и 4+1, сохраняя существующие цены и редакторские правки. Повторный запуск не создаёт дубликатов.

## Источники и ограничения

- Источник: [папка пользователя в Google Drive](https://drive.google.com/drive/folders/1x1X8zAy022W7Pwrb5BDJiP33BoYHBV9e). Идентификаторы изображений сохранены в скрипте импорта.
- Название, адрес, RAMS/ETRO, комплектации Standard/Premium и концепция инфраструктуры взяты из презентации. Все изображения помечены как визуализации.
- Диапазоны: 1+1 — 101,35–113,10 м² / $990 000–1 509 000; 2+1 — 144,87–172,71 м² / $1 824 000–2 179 000; 3+1 — 210,55–274,70 м² / $2 435 000–3 540 000.
- 24.06.2025 — дата изменения исходного файла Price Range в Drive, **не дата подтверждения действующего предложения**. Начальный статус цен — `indicative`. Актуальные цены и наличие требуют подтверждения у продавца.
- Площадь в прайсе и net/полезная площадь на планах различаются. На сайте это оговорено; планы не перерисовывались.
- В презентации, стр. 16, подтверждён также формат **4+1**. Его цены, площади и отдельного плана в представленных коммерческих материалах нет: эти поля равны `null`, отображаются «по запросу». Поиск по 4 спальням находит комплекс, числовые фильтры не считают неизвестные величины нулём.
- Точные примеры планов: T1 A1 (1+1) — gross 113,10 / net 60,71 / net с балконом 68,91 м²; A07 (2+1) — 170,16 / 97,68 / 106,72; A05 (3+1) — 271,82 / 154,32 / 170,38; T1 A2 (3+1) — 216,81 / 122,16 / 138,42. Сохраняются в `plan_details`, доступны в админке и показаны под выбранной планировкой. Диапазоны цен относятся к типам, а не отдельным планам.
- Дополнительный 60-страничный `ETRO Residences dayarea-nightarea.pdf` проверен: внутри представлен интерьерный mock-up 3+1 и несколько дизайн-предложений; они не выдаются за новые доступные квартиры. Обозначение 4+1 на странице-содержании этого файла расходится с маркировкой самого плана 3+1. Для 4+1 используется однозначное подтверждение из основной презентации, а не спорный чертёж.
- Срок сдачи, условия оплаты, доходность, гражданство и наличие конкретных квартир не выдумывались. Отдельные услуги комплекса могут оплачиваться дополнительно.
- Галерея — анимированные оригинальные изображения с паузой и увеличением, а не 3D-тур или AI-видео. При `prefers-reduced-motion` движение отключено. TrueSpace проверен как возможный инструмент; аккаунт и платная генерация не использовались.

## Управление

В админке объектов выбрать «Жилой комплекс с вариантами квартир». Задать валюту, редактировать переводы, инфраструктуру, интерьерные изображения и варианты квартир. Первое изображение общей галереи — обложка, второе — иллюстрация расположения. Презентация задаётся ссылкой.

Шаблон `DevelopmentPage` общий для ETRO и любых новых ЖК; проверок slug для выбора оформления нет. Разделы «О проекте», «Интерьеры», «Резиденции», «Расположение» и их пункты меню зависят от заполненных данных. Пустая интерьерная галерея скрывается, а не подменяется фотографиями фасада. Галерея — широкоформатный баннер с ручным переключением, паузой и увеличением; экспериментальные последовательные скролл-сцены больше не подключаются.

Для нового ЖК формат автоматически выбирает категорию `residential-development` и режим черновика. Кнопка «Предпросмотр ЖК» открывает текущие несохранённые данные в том же компоненте страницы: 4 языка, галерея, планы и выбор типа. Предпросмотр ничего не сохраняет и не отправляет заявки; внешние переходы заблокированы, закрытие возвращает в редактор без потери полей. Публикация — отдельное действие: включить «Опубликован на сайте» и сохранить. Для сохранения, включая черновик, требуется хотя бы один тип с ценой. Изображения интерьеров и планировок можно переставлять кнопками; удаляются только ссылки, файлы остаются на диске.

## Второй комплекс для проверки

`docker compose exec -T api python -m app.seed_demo_development` добавляет **Beylikdüzü Park — DEMO** по адресу `/ru/properties/demo-beylikduzu-park` (также EN/TR/AR). Повторный запуск ничего не заменяет. Это вымышленный комплекс в Бейликдюзю, не реальное предложение. Иллюстрации и схемы SVG созданы специально для демонстрации; цены и площади тестовые. У 1+1–3+1 заданы диапазоны и схемы, у 4+1 — значения «по запросу» для проверки пустых данных.

Профиль `is_demo: true` показывает явное предупреждение на странице и карточке. Такой объект виден в локальном каталоге и фильтрах, но принудительно исключён из рекомендаций, получает `noindex` и отсутствует в sitemap/ApartmentComplex JSON-LD. Форма и контактные действия отключены; API также отвергает формы, tracking и webhook с ID демо-объекта до создания лида.

Кнопки загрузки поддерживают JPEG, PNG, WebP, GIF и сохраняют файлы в существующее хранилище `/uploads/properties`. Требуются авторизация, право `properties:write` и CSRF. Удаление ссылки из карточки не удаляет файл с диска. Если перевод редакционных полей отсутствует, используется EN, затем RU.

Цена и площадь «от» выводятся из минимальных значений вариантов. `rooms` для типа квартиры — число спален до `+1`; комнаты комплекса не суммируются. Все фильтры должны совпасть на одном типе квартиры. Контракт ценового фильтра — RUB: цена каждого объекта/типа переводится из его валюты по сохранённым курсам ЦБ. Сортировка учитывает валюту. Если конвертация ещё недоступна, отображается исходная цена с исходной валютой.

Заявка содержит ID комплекса и выбранный тип в сообщении. Сам комплекс нельзя закрыть как проданный/сданный через CRM: для сделки нужно создать отдельный объект конкретной квартиры и заявку на него. Это защищает все остальные резиденции от случайного закрытия. Учёт наличия по этажам/номерам квартир в этот этап не входит.

После «Узнать наличие» в заявку также попадает код выбранной планировки и её gross-площадь. При ручной смене типа в форме уточнение плана сбрасывается.

Быстрые категории на главной ведут сразу в отфильтрованный каталог и сохраняют введённый поиск/бюджет. «Жилые комплексы» заменяют «Участок» только в быстром ряду; участки остаются в базе и полном фильтре. На главной сохранён исходный sticky-hero: следующий контент поднимается поверх первого экрана. Работа над общим шаблоном ЖК не меняет главную.

## Проверки

```bash
docker compose exec -T -e RUN_DB_TESTS=1 api python -m unittest discover -s tests -v
docker compose exec -T api alembic check
cd frontend
npx tsc --noEmit
npm run lint
npm run test:developments
# При запущенном локальном сайте и добавленном демо:
node tests/development-http-smoke.cjs
```

Интеграционные тесты используют отдельную транзакцию PostgreSQL с savepoint и откатывают все тестовые записи. Проверяют CRUD, сохранение ID вариантов, совместные фильтры, конвертацию и сортировку, скрытие неактивного комплекса и запрет продажи комплекса целиком.

Проверено 08.09.2026: 22 backend-теста (включая PostgreSQL), 7 тестов данных шаблона, 14 регрессий скролла/архивного проигрывателя; HTTP-проверки ETRO и DEMO, всех четырёх языков, SVG-ресурсов и sitemap. В браузере проверены несохранённый текст, закрытие предпросмотра без потери полей, скрытие пустой галереи и её ссылки, выбор DEMO-2A, пауза и увеличение изображения, мобильная ширина 390 px без переполнения. У ETRO выбор T1 A2 переносится в блок заявки, смена типа сбрасывает план; реальные заявки в ходе проверки не отправлялись. Новый ЖК выбирает правильную категорию и черновик. Главная при scrollY=0/252 сохраняет heroY=0, контент смещается с 720 до 468 px.
