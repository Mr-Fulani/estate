# Технический долг

## Двусторонняя почта `support@rahathome.com`

**Статус:** отложено, требуется разработка и настройка почтовой инфраструктуры.

Сейчас форма на странице «Контакты» не отправляет email: она создаёт лид в CRM, а адрес `support@rahathome.com` используется только как публичная ссылка `mailto:`. В будущем нужно сохранить CRM основным источником обращений и добавить полноценный почтовый канал.

### Требуемый результат

- отправлять на `support@rahathome.com` уведомление о каждой новой заявке с сайта;
- позволить сотруднику ответить клиенту от имени `support@rahathome.com`;
- принимать входящие письма на `support@rahathome.com` и создавать новый лид либо добавлять сообщение в историю существующего диалога;
- связывать ответы с лидом по устойчивому идентификатору переписки, не создавая дубликаты;
- сохранять в CRM направление письма, отправителя, получателей, тему, текст, время, внешний ID и статус доставки;
- отображать ошибки отправки и предусмотреть безопасные повторные попытки;
- журналировать административные действия без сохранения почтовых секретов в логах.

### Что потребуется настроить

- выбрать почтового провайдера с API отправки и webhook для входящих писем;
- подтвердить домен и настроить SPF, DKIM и DMARC;
- добавить отдельные production-секреты для API и проверки подписи webhook;
- определить политику вложений, лимиты размера, антивирусную проверку и срок хранения переписки;
- добавить идемпотентную обработку входящих webhook, защиту от подделки и rate limiting;
- настроить очередь, повторные попытки, мониторинг отказов и уведомления о недоставленных письмах.

### Критерии завершения

1. Заявка с сайта всегда сохраняется в CRM независимо от доступности почтового провайдера.
2. Новая заявка вызывает email-уведомление на `support@rahathome.com`.
3. Входящее письмо появляется в CRM один раз и относится к правильному лиду или создаёт новый.
4. Ответ из CRM отправляется клиенту от `support@rahathome.com`, а его статус виден сотруднику.
5. Ошибки, повторные попытки, подпись webhook и сопоставление цепочек покрыты тестами.
6. Production-настройка домена, секретов, мониторинга и инструкция по эксплуатации документированы.
